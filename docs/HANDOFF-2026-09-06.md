## 9 · The data, exactly

Supabase table `store`, key/value JSON, read with the owner seat signed in.

```js
const get = async (k) => (await sb.from('store').select('value').eq('key', k).maybeSingle()).data?.value ?? null;
```

| Key | Shape | Tonight |
| --- | --- | --- |
| `expo-bhbc-roster` | array of athletes | 10 |
| `expo-bhbc-loads` | object keyed by athlete id | 10 |
| `expo-bhbc-fixtures` | array | 33 |
| `expo-bhbc-medical` | object keyed by athlete id | 8 |
| `expo-bhbc-plans` | object keyed by `date\|start` | 1 |

**roster[i]** — `id, name, jersey, position, nationality, dob, age, height,
heightCm, weight, team, format, goals, status, arrival, startDate, injuries`

**loads[athleteId]** — `{ loads, sessions, readiness, attendance, availability }`

```json
sessions["2026-09-06"][0] = {
  "by": "ohadyproductions@gmail.com",
  "min": 90, "rpe": null, "load": 0,
  "team": true, "type": "Practice", "start": "16:00", "attended": true
}
availability = { "2026-08-19": 1, "2026-08-23": 1 }
```

`type` on a LOGGED row is the capitalised label a coach picked — `Practice`,
`Lift`, `Shootaround`, `Game`. On a FIXTURE it is lowercase — `practice`,
`lift`, `game`. Code matching them must map between the two; `PastPractices`
holds the canonical helper.

**medical[athleteId].injuries[0]** — `{ by, id, pain, side, type, notes, status,
bodyPart, progress[], onsetDate, rtpTarget, … }`. `status` is
`available | limited | non-contact | out` and sets a FLOOR on availability: a
coach can make a day worse than the medical fact, never better.

**fixtures[i]** — `{ date, type, start, end, minutes, optional }` plus, new and
optional, **`contactMin`**. Absent means no density is shown. Written only by
the week-planner editor.

**plans[`${date}|${start}`]** — `{ focus, plan, updatedAt }` — where "what the
room did" gets its words.

### Non-negotiable data rules

1. **RPE is never invented.** Every gym row this project writes carries
   `rpe: null, load: 0`. 72 lift sessions are stored; not one has a fabricated
   RPE.
2. **Snapshot before any write** and read back after — `scripts/bhbc-log-lift.mjs`
   and `audit-out/test-density.mjs` both do it; copy the pattern.
3. **Never derive a per-client amount from the roster sheet.** It holds a rate
   and sessions-since-payment, which is not what was paid.
4. **Revenue is owner-only** — `revenue_sheet_event`, `revenue_month_total`.
   `bit_payment_requests` is athlete-readable. `scripts/verify-revenue-private.mjs`
   proves the isolation from five seats.

## 12 · Design — the taste rules and the scars

**EXPO:** dark `#0a0a0b`, cyan `#39BDFF`. The cyan never deepens.
**Bnei Herzliya:** the zone is **always light**. Navy `#1E3D74`, deep navy
`#14294F`, orange `#F26A2B`, deep orange `#D9541A`.

```js
const TOKENS = {
  '--c-ac': NAVY_DEEP,
  '--c-stripBg': NAVY_DEEP,
  '--c-cardBd': 'rgba(30,61,116,0.26)',   // a NAVY hairline, not a mix with EXPO's
  '--c-bd':     'rgba(30,61,116,0.22)',
  '--bhbc-amber-text': '#8A6410',          // the LIGHT-page amber, pinned
};
```

Two scars in that block: mixing 20% navy into `--c-bd` left EXPO's cyan showing
through every card edge, which made a club popup read as an EXPO dialog; and
`--bhbc-amber-text` is declared twice on `:root`, so with EXPO in dark mode the
zone painted the dark-page amber on white — **2.15:1**, unreadable, on every
"limited" count. **Every BHBC modal carries these tokens**, because a modal is
portalled to `body`.

| Rule | Why |
| --- | --- |
| No icons or emoji — "just colors" | a triangle before every injured athlete was noise |
| Plain coloured text, not badges, in tight rows | badges add invisible padding |
| Measure the **ink**, not the box | he reported one pill 3×; the box was centred to 0.00px, the glyphs rode 0.6px high |
| Every card gets a strip header | `RefinedHeaderStrip` |
| Uniform strips: 13px, 0.04em, 14/14 | |
| Fixed-size toggles reserve the widest label | resizing reads as a flash bug |
| ≤0.5px borders do not render | screenshot-verify |
| Layout identical light/dark; only colour differs | |
| RTL: forward arrow `←` at the logical end; `‹` where `›` would be | |
| Hebrew sits +3px INSIDE the box | never taller boxes |
| The real font is **Nord** | `public/fonts/Nord-*.woff2`; CLAUDE.md is stale |

Decisions made tonight: the grid fills its card; future days are not columns;
the gap sits on the row and the due list is one strip; the chevron turns with
the text; Hebrew names beside Latin numbers need `unicode-bidi: isolate`; the
printed row is two columns with a cyan spine; the print masthead is a black band
with the mark on a white plate.

**What "too spacious" meant:** three rules added for the OPPOSITE complaint — a
266mm day floor, a 17mm row floor, and cues under the name across the full
width. Removing all three took Day A from ~1,400px to ~810px. If density is ever
complained about again, do not re-add a floor; look at what is actually empty.

### Probe traps that have cost real time

1. Clicking tabs by **English label** measures one tab five times in Hebrew.
   Click by INDEX; identical word counts on every line is the tell.
2. `sessionStorage.clear()` alone leaves the previous seat signed in — the
   Supabase session is in `localStorage`.
3. The zone has **its own** language switch (`עב`); `expo-lang` does not move it.
4. CSS `text-transform` hides words from grep — the DOM said `Update`, the
   screen said `UPDATE`.
5. Measuring straight after a viewport resize catches an empty frame.
6. Lazy images never render in a full-page capture.
7. A `file://` screenshot of a PNG hangs the shooter for its whole timeout.
8. The service worker reloads after a rebuild: "detached Frame" means retry.
9. `execSync` + `curl -w "%{http_code}"` → cmd.exe eats the `%`; use `http.get`.
10. `execSync` + `git cat-file -e ${sha}^{commit}` → cmd.exe eats the `^`.
