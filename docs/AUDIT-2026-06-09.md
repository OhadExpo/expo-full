## Top 10 by ROI — ship-this-week list

1. **`api/push/send.js:38-135` — any authenticated user can send a spoofed push to any other user.** HIGH · trivial. The handler resolves the caller only to log, never to authorize; `toEmail`/`title`/`body`/`url` are caller-supplied. An athlete can push "EXPO: confirm your payment" to another athlete's devices. Fix: reject unless `callerEmail === toEmail` or `is_staff(callerEmail)`.

2. **`api/meal-macros.js` — unauthenticated paid-LLM endpoint, zero rate limit.** HIGH · small. Verified: no `Authorization` check, no rate bucket anywhere in the file. Anyone with the URL burns the Anthropic key in a loop. Fix: Bearer-token gate (pattern exists in `api/push/subscribe.js`) + the per-IP bucket the other endpoints use.

3. **VERIFY PROD — one `pg_policies` batch, five questions.** Potentially BLOCKER · trivial to check. (a) `client_workouts` + `bw_logs` SELECT: committed `supabase-rls-auth.sql:50-75` grants read to *any* authed user → cross-athlete IDOR if prod matches; (b) `store` key `expo-portal-vis` athlete-read: if the 06-06 lockdown blocked it, every coach show/hide override is silently ignored on the real portal; (c) `weekly_focus` athlete-read: if blocked, athletes see "No focus set this week" forever; (d) `coaching_contracts` UPDATE: column scope + `athlete_signed_at IS NULL` guard — else a token holder can re-sign/tamper a signed contract; (e) `bookings` INSERT WITH CHECK vs client-supplied `status:'confirmed'`/`start_at`/`duration_min` (`src/BookingPublic.jsx:137`). None of these failures throw — all degrade silently. RLS drift from repo SQL is a known incident pattern; query prod, don't trust the files.

4. **`src/PlansView.jsx:156` — ExerciseBrowserModal missing `role="dialog"`.** HIGH UX · trivial (one attribute). Verified: the compare wheel handler exempts `[role="dialog"]` (line 713) and this modal never sets it — wheeling over the open Add/Swap modal scrolls the compare panes behind it and `preventDefault` kills the modal's own list scroll.

5. **`src/PlansView.jsx:820` — compare breakout `transform:translateX(-50%)` becomes the containing block for `position:fixed` modals.** HIGH UX · small. ExerciseBrowserModal, row ExPickers, and ConfirmDialog all render inside the wrapper — with compare open, scrims/centering anchor to the wrapper, not the viewport. Fix: portal the modals to `document.body`, or replace the transform centering with `marginLeft:'calc(50% - min(48vw,1200px))'`.

6. **`src/PlansView.jsx:1312-1315` — duplicating a plan silently resets it to 4 weeks and drops the daily-routine flag.** MEDIUM data-integrity · trivial. `handleDuplicate` omits `weeks` and `kind`; `savePlan` defaults `weeks: plan.weeks || 4`. A duplicated 6/8-week plan truncates to W1–W4. Fix: pass both through.

7. **`src/DashboardView.jsx:59-62` (+ `TraineesView.jsx:366`) — null trainee `name`/`status` white-screens the dashboard, and Smart Import can create exactly that row.** MEDIUM-HIGH · trivial. `SmartImportView.jsx:370-376` commits athletes without requiring `name`. Fix: `(t.name||'')` guards + reject nameless rows at import commit.

8. **`src/ClientPortal.jsx:255 + 823` — restored workout draft can crash the athlete portal until the draft is manually cleared.** MEDIUM · small. Draft `step:'wu2'` outlives a plan edit that shrank warm-ups → `warmup[wi].vid` TypeError on every load (drafts never expire). Fix: clamp restored `step` against current `wuCount`/`groupCount`.

9. **`src/ProgramShare.jsx:150` — shared links render old-shape plans as empty.** MEDIUM · small. Verified: `PlanReadOnly` reads only `d?.exercises`; the 174 old-shape plans use `d.ex`/`eid`/`s`/`r`. Any pre-2026 plan shared via `/p/<token>` shows day cards with zero exercises. Fix: normalize both shapes (reuse `normalizeDays`).

10. **`src/DashboardView.jsx:318-346` — one failed plans fetch spawns up to ~20 spurious "no plan" auto-tasks.** MEDIUM · trivial. The query's `.error` is ignored; `planList=[]` feeds `syncAutoTasks`. Fix: skip sync when the read errored.
